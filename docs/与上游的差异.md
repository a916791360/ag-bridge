# 与上游的差异

本文件逐条列出 AG Bridge 相对上游 [Antigravity Bridge](https://github.com/anzaiyes/AntigravityBridge) v2.2.0 的改动，
便于审阅，也便于上游发新版时把改动重新应用一遍。

基线：`anzaiyes/AntigravityBridge` @ v2.2.0
产出：AG Bridge v1.0.0

## 一、同时支持两个 Antigravity App（功能修复）

Google 已把 Antigravity 拆分为两个独立 App：

| Bundle ID | App |
| --- | --- |
| `com.google.antigravity-ide` | Antigravity IDE |
| `com.google.antigravity` | Antigravity（agent manager） |

上游只认 `com.google.antigravity-ide`。只安装 agent manager 的机器上，上游会直接判定「未找到 Antigravity」——即使 `--configure` 让用户手动挑选，也会因为 Bundle ID 不在白名单里而被再次拒绝。

改动：

- 新增 `ACCEPTED_BUNDLE_IDS=("com.google.antigravity-ide" "com.google.antigravity")`。
- `verify_antigravity_bundle` 由单值比较改为遍历白名单。
- `find_antigravity` 的 Spotlight 兜底查询对两个 Bundle ID 各查一次。
- 应用选择窗口与告警文案去掉「IDE」限定词。

## 二、修复启动器永久卡死（严重缺陷）

上游判断 Antigravity 是否在运行时执行：

```bash
app_running="$(/usr/bin/osascript -e 'application "Antigravity IDE" is running' 2>/dev/null || true)"
```

当机器上不存在显示名恰为 `Antigravity IDE` 的 App 时，`osascript` 不会报错返回，而是**永久阻塞**。表现为：双击启动器后毫无反应、启动器进程一直挂着不退出、Antigravity 也不会被拉起。

改动：改为按真实可执行文件路径探测，与显示名完全解耦。

```bash
if /usr/bin/pgrep -f "$ANTIGRAVITY_PATH/Contents/" >/dev/null 2>&1; then
  app_running="true"
else
  app_running="false"
fi
```

## 三、配置迁移覆盖两条旧路径

上游只从 `~/Library/Application Support/Antigravity Proxy/` 迁移。改动后按新到旧依次尝试：

1. `~/Library/Application Support/Antigravity Bridge/`（上游 AG Bridge 之前叫这个名字）
2. `~/Library/Application Support/Antigravity Proxy/`

`migrate_legacy_config` 由单值改为遍历 `LEGACY_CONFIG_ROOTS` 数组，并且**已存在配置时绝不覆盖**。
旧目录不会被删除。

## 四、品牌化

| 项目 | 上游 | AG Bridge |
| --- | --- | --- |
| 应用名 | Antigravity Bridge | AG Bridge |
| Bundle ID | `com.tinybye.antigravity-bridge` | `io.github.a916791360.ag-bridge` |
| 可执行文件 | `antigravity-bridge` | `ag-bridge` |
| 图标文件 | `AntigravityBridge.icns` | `AGBridge.icns` |
| 配置目录 | `Application Support/Antigravity Bridge/` | `Application Support/AG Bridge/` |
| 主环境变量 | `ANTIGRAVITY_BRIDGE_CONFIG_DIR` | `AG_BRIDGE_CONFIG_DIR`（旧名兼容） |
| 库模式变量 | `ANTIGRAVITY_PROXY_LIBRARY_ONLY` | `AG_BRIDGE_LIBRARY_ONLY`（旧名兼容） |
| 发布产物 | `Antigravity-Bridge-v<版本>-*` | `AG-Bridge-v<版本>-*` |
| 版本号 | 2.2.0 | 1.0.0（独立版本线） |

全部弹窗标题、按钮文案、`--help` 输出与文档都已改为新品牌。
`BUNDLE_ID` 常量被 `ACCEPTED_BUNDLE_IDS` 取代，脚本内不再有单值 Bundle ID 引用。

## 五、命令行参数

新增两个参数，均为只读、不产生副作用：

```bash
ag-bridge --version   # 打印版本号
ag-bridge --help      # 打印用法与配置文件位置
```

版本号在 `src/ag-bridge` 顶部的 `BRIDGE_VERSION` 中维护，测试会断言它与
`packaging/Info.plist` 的 `CFBundleShortVersionString` 一致。

## 六、图标

上游 `.icns` 只含 5 个尺寸（16 / 32 / 128 / 256 / 512，无 @2x）。
AG Bridge 的 `.icns` 由 1254×1254 源图生成，含 16 → 1024 共 10 个尺寸，覆盖全部 @2x 场景。

源图内容为 1027×1003 的圆角方块，四边留白 113 / 126 / 114 / 125，占画布 81.8%，
与 macOS 图标惯例的 80.5% 基本一致，因此按原图直接缩放，未做额外裁切或补边。

## 七、测试

在保留上游全部用例的基础上新增：

| 用例 | 目的 |
| --- | --- |
| 两个 Bundle ID 都被接受 | 锁定第一节的修复 |
| 无关 Bundle ID 被拒绝 | 防止白名单被改宽 |
| 无 `Contents/Info.plist` 的路径被拒绝 | 防止误判 |
| `BRIDGE_VERSION` 与 `Info.plist` 一致 | 防止 `--version` 与实际版本漂移 |
| 从 `Antigravity Bridge` 迁移成功且权限为 600 | 覆盖第一条旧路径 |
| 从 `Antigravity Proxy` 迁移成功 | 覆盖第二条旧路径 |
| 已存在配置不被覆盖 | 防止迁移破坏现有配置 |
| 打包产物包含图标且与源文件一致 | 防止图标漏打进包 |

迁移相关用例调用的是 `src/ag-bridge` 里的真函数（只把 `CONFIG_ROOT` 等全局变量指向临时目录），
不在测试里重写一遍逻辑，避免出现「测副本、真代码坏了照样绿」的假阳性。

## 上游发新版时怎么同步

```bash
git remote add upstream https://github.com/anzaiyes/AntigravityBridge.git
git fetch upstream
git diff upstream/main -- src/ tests/
```

上游改动集中在 `src/antigravity-bridge` 与 `tests/run-tests.sh`。把上游改动应用到
`src/ag-bridge` 与 `tests/run-tests.sh` 时，注意上面第一至第四节涉及的符号在 AG Bridge 中已改名，
合并后务必跑一次 `./tests/run-tests.sh`。
