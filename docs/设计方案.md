# AG Bridge v1 Design

## Goal

Provide a portable native macOS application launcher that starts Antigravity with a process-scoped local proxy, without requiring TUN mode, changing global proxy settings, or keeping a terminal window open. Support Clash Verge, ClashX, Surge and compatible HTTP/SOCKS listeners.

## Architecture

The deliverable is a minimal macOS App Bundle. Its executable is a Bash script launched by Finder or Dock. Discovery reads the active macOS system proxy, known Clash/Mihomo YAML files, and Surge profiles, then probes common listener ports. Every candidate is validated with its declared HTTP or SOCKS protocol before it is shown. Mixed listeners are used as HTTP proxies.

Candidates receive an explainable recommendation score. Successful access to the Antigravity service endpoint has the highest weight, followed by HTTP/Mixed compatibility, loopback-only binding, and a known system/client source. The highest-scoring option is moved to the top, prefixed with `★ 推荐`, selected by default, and accompanied by a plain-language reason in the selection prompt.

On first run the user chooses a validated candidate or enters a type and port manually. The selection and discovered Antigravity path are saved in the current user's `~/Library/Application Support/AG Bridge/config.plist`. Legacy configuration is copied during migration, searched in order: upstream `Antigravity Bridge`, then the older `Antigravity Proxy`. Subsequent launches reuse the configuration while it remains valid, and return to discovery when it does not.

## Antigravity discovery

Google has split Antigravity into two separate macOS apps, so the launcher accepts both bundle identifiers:

| Bundle ID | App |
| --- | --- |
| `com.google.antigravity-ide` | Antigravity IDE |
| `com.google.antigravity` | Antigravity (agent manager) |

Discovery first verifies common `/Applications` and `~/Applications` locations for both identifiers, then queries Spotlight for each of them in turn, with a native application picker as fallback. The same whitelist is used to validate a manually picked app, so an unrelated bundle is always rejected.

## Runtime state check

To decide whether Antigravity is already running, the launcher probes for processes whose executable path lies under the resolved app bundle (`pgrep -f "$ANTIGRAVITY_PATH/Contents/"`).

An earlier implementation queried AppleScript with `application "Antigravity IDE" is running`. That blocks indefinitely when no installed app carries that display name — which is the normal case when only the agent manager is installed — and takes the launcher down with it. Path-based probing is independent of the display name and does not block.

## Launching

Launching uses macOS `open --env` to inject proxy variables into the new Antigravity process tree. Chromium proxy flags cover Electron traffic, while `NO_PROXY` and the Chromium bypass list preserve Antigravity's localhost bridge.

The launcher exits immediately after a successful launch. Antigravity and `language_server` retain their inherited environment independently.

## Error Handling

- Missing Antigravity: show a native alert and exit.
- No detected proxy: offer manual HTTP/Mixed or SOCKS5 configuration.
- Invalid or unavailable selected proxy: do not save it; show a native alert and retry on the next launch.
- Stale saved proxy: rerun discovery and selection automatically.
- Antigravity already running: do not quit it automatically; explain that the current process cannot be retrofitted with environment variables.
- Launch failure: show the returned status in a native alert.

## Acceptance Tests

1. `Info.plist` passes `plutil -lint`.
2. Executable passes `bash -n`.
3. Diagnostic mode discovers the locally running proxy with the correct protocol and port.
4. Configuration round-trip tests pass in an isolated temporary user directory.
5. Both supported bundle identifiers are accepted, and an unrelated bundle is rejected.
6. Legacy configuration is migrated from either legacy directory, and an existing configuration is never overwritten.
7. `BRIDGE_VERSION` equals `CFBundleShortVersionString` in `Info.plist`.
8. Bundle reports the expected identifier, executable, and icon.
9. App is ad-hoc code signed for unnotarized builds and passes `codesign --verify`.
10. Launcher contains no command that changes proxy clients, system proxy, routes, or the original Antigravity bundle.
11. HTTP and SOCKS launch URLs are constructed correctly and localhost is bypassed.
12. Release ZIP contains no `.DS_Store`, AppleDouble, or `__MACOSX` entries and its SHA-256 verifies.
