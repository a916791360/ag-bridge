# AG Bridge 使用说明

## 支持范围

- Antigravity IDE（`com.google.antigravity-ide`）与 Antigravity（`com.google.antigravity`，即 agent manager）
- Clash Verge / Clash Verge Rev
- ClashX / ClashX Meta
- Mihomo Party 及兼容 Clash YAML 配置的客户端
- Surge for Mac
- macOS 当前启用的 HTTP、HTTPS 或 SOCKS 系统代理
- 任意在本机监听的 HTTP/Mixed 或 SOCKS5 代理

## 首次运行

1. 保持代理客户端核心运行，TUN 可以关闭。
2. 如果 Antigravity 已打开，用 `Command-Q` 完全退出。
3. 双击 `AG Bridge.app`。
4. 启动器会寻找 Antigravity，并验证检测到的代理端口。
5. 从弹出的列表选择一个代理；也可以选择“手动配置…”，输入类型和端口。

列表会将评分最高的候选项移到首位、标记为 `★ 推荐` 并默认选中。推荐优先考虑：能够访问 Antigravity 专用端点、HTTP/Mixed 兼容性、本机回环监听，以及可信的系统或客户端配置来源。

配置保存在当前用户的：

`~/Library/Application Support/AG Bridge/config.plist`

从上游 Antigravity Bridge 或更早的 Antigravity Proxy 升级时，启动器会依次在这两个旧目录中查找配置并自动复制过来，不需要重新选择代理。

不同 macOS 用户拥有各自独立的配置。配置的代理失效或端口发生变化时，启动器会自动重新探测并再次询问。

## 日常使用

把 `AG Bridge.app` 拖入 `/Applications` 或固定到 Dock。以后从这个图标启动 Antigravity。启动器完成启动后会自动退出，不需要保持任何窗口打开。

> 直接双击 Antigravity 本身的图标不会带代理。要带代理，必须从 AG Bridge 启动。

## 自动发现逻辑

- 在 `/Applications`、`~/Applications` 和 Spotlight 中按 Bundle ID 查找 Antigravity。
  依次尝试 `com.google.antigravity-ide`（Antigravity IDE）与
  `com.google.antigravity`（Antigravity / agent manager），两者都找不到时弹出应用选择窗口。
- 读取 macOS 系统代理。
- 读取 Clash/Mihomo 的常见活动配置文件。
- 读取 Surge Profile 的 `http-listen` 和 `socks5-listen`。
- 探测 Clash 和 Surge 常用端口。
- 候选端口必须通过对应 HTTP 或 SOCKS 协议连接验证，才会显示在列表中。

## 行为边界

- 只代理 Antigravity 进程树。
- 不打开 TUN。
- 不修改系统代理、路由或代理客户端配置。
- 不修改 Antigravity 应用。
- 不读取、保存或转发 Google 登录凭据。

## 重新配置和诊断

如果已保存的代理无法使用，下一次启动会自动重新配置。

也可以在终端主动重新配置：

```bash
"/Applications/AG Bridge.app/Contents/MacOS/ag-bridge" --configure
```

查看自动发现结果：

```bash
"/Applications/AG Bridge.app/Contents/MacOS/ag-bridge" --diagnose
```

查看版本或全部参数：

```bash
"/Applications/AG Bridge.app/Contents/MacOS/ag-bridge" --version
"/Applications/AG Bridge.app/Contents/MacOS/ag-bridge" --help
```

## 为什么不会卡死

启动器需要先确认 Antigravity 没有在运行——已经跑起来的进程无法补加环境变量，只能提示你退出后重试。

上游用 AppleScript 按应用名 `"Antigravity IDE"` 查询运行状态。如果机器上的 App 不叫这个名字（例如只装了 agent manager），`osascript` 会一直阻塞不返回，表现为双击启动器后毫无反应、进程也退不掉。

AG Bridge 改为按真实可执行文件路径探测，与 App 显示名无关，因此不会出现这种情况。
